# 接入已有任务系统

已有业务服务可以逐个转换为 HTTP 步骤，不需要把其数据库和 SDK 引入调度引擎。

| 已有实现 | 对应配置 |
| --- | --- |
| 顺序任务列表 | 用 `depends_on` 连接成依赖链 |
| 可同时执行的任务 | 使用相同前置节点，不互相依赖 |
| 等待 HTTP 结果 | `type: http`，`execution_mode: sync` |
| 后台任务和外部状态通知 | `execution_mode: async`，处理完成后调用统一上报 SDK / 接口 |
| 可忽略的非关键步骤 | 配置传播策略及 `affects_run: false` |
| 固定执行时间段 | 带时区的流程时间窗口 |

业务字段放入 `input`，由接入服务负责校验。若已有服务只提供 RPC，可在业务侧加 HTTP 适配层；若其任务通过消息队列处理，在消息中保存限时回调地址，处理结果持久化后再上报。

迁移前确认重试次数是否包含首次执行、业务幂等键的范围、失败是否允许后续继续，以及旧任务的外部副作用。已有运行实例宜在原系统完成，新任务逐步切换，不应仅依据表结构复制执行中的状态。

详见 [工作流配置](workflows.md)、[异步开发指南](async-workers.md) 和 [架构说明](architecture.md)。
